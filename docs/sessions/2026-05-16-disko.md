# disko: declarative disk layout for fresh installs

date: 2026-05-16
status: shipped

## Context

`scripts/host-setup.sh` had three modes that encoded disk layout in
bash: `--partition` (wipe + mkfs + subvols), `--mount` (mount the
expected layout under /mnt), and `--install` (regen hwconfig, git
add, nix eval verify, nixos-install, then a
`provision_swap_and_offset` step that created `/swap/swapfile`,
captured its physical offset via `btrfs inspect-internal
map-swapfile`, patched the host bridge's `boot.kernelParams`,
re-staged it, and re-ran nixos-install so first boot resumed from
hibernate correctly).

Each fresh install replayed the same bash partition geometry. The
hardware-configuration.nix files were UUID-pinned to the random
UUIDs produced during the most recent mkfs run — fine while
nothing changed, fragile under reimage. Adding a new host meant
copying pb-x1.nix and praying the disk happened to be NVMe (the
script's `PSEP=p` vs `PSEP=""` detection was correct, but the layout
itself was implicit).

User asked: "could we use disko for managing disks during host
setup?"

## Decision

Re-image every host, with disko owning disk layout as the single
declarative source of truth. Disko's NixOS module synthesises
`config.fileSystems.*` and `config.swapDevices` at evaluation time
from `disko.devices`, and also publishes
`config.system.build.diskoScript` — an executable that wipes +
partitions + formats + mounts the declared layout. Same spec
drives both install-time and runtime.

Two layout templates, parameterised by disk device, shared across
host classes:

**bare-metal** (pb-x1, pb-t480, m-pc) — hybrid GPT with a 1 MiB
bios-boot partition + 1 GiB vfat ESP + btrfs with subvols
`root`/`nix`/`home`/`swap`/`snapshots`. The bios-boot partition
lets the same layout boot on m-pc's Compaq SFF (BIOS firmware, grub
target) and the laptops (UEFI, systemd-boot) without per-host
divergence. `compress=zstd:1` on everything except swap; swap
subvol is `nodatacow,noatime` so NixOS's
`mkswap-swap-swapfile.service` can create the file there without
needing `chattr +C`.

**vm** (ah-1 and any future Proxmox guest) — UEFI-only, 1 GiB
vfat ESP + ext4 root. No swap, no subvols. Reason: the Proxmox
storage stack is NFS-mounted from a TrueNAS server running ZFS, so
ZFS already provides CoW + checksums + snapshots + integrity at
the bottom of the stack. Guest btrfs would be 3× CoW (btrfs in
guest + qcow2 + filesystem on ZFS) for no gain. ext4's lighter
journal also wastes fewer NFS round-trips.

## Dendritic shape

`flake-modules/disko.nix` publishes:

- `flake.modules.nixos.disko` — wraps `inputs.disko.nixosModules.disko`
- `flake.lib.diskoLayouts.bare-metal = { disk }: <module>`
- `flake.lib.diskoLayouts.vm        = { disk }: <module>`

Host bridges inline both:

```nix
configurations.nixos.pb-x1.module.imports = [
  config.flake.modules.nixos.disko
  (config.flake.lib.diskoLayouts.bare-metal { disk = "/dev/nvme0n1"; })
  ...
];
```

The disk path lives in the bridge, not in a per-host
`hosts/<name>/disko.nix`, because plain NixOS modules don't have
access to flake-parts' `config` (NixOS `config` ≠ flake-parts
`config`). The bridge already owns every other per-host knob.

## hardware-configuration.nix migration

All four hosts' hardware-configuration.nix files lost their
`fileSystems.*` and `swapDevices` blocks — disko provides them. The
`m-pc` and `ah-1` placeholder files dropped the sentinel-UUID
`fileSystems."/".device` assertion (no `fileSystems` left to assert
on) in favour of a plain `builtins.getEnv "NIXOS_ALLOW_PLACEHOLDER"
== "1"` env check. Every file's header documents the
`--no-filesystems` flag mandatory for any future regeneration.

## host-setup.sh simplification

- Deleted `--partition` and `--mount` modes entirely.
- Deleted `provision_swap_and_offset` (≈250 lines): with disko
  providing a pre-formatted nodatacow `/swap` subvol, the
  install-time swapfile-create + offset-capture + bridge-patch +
  reinstall dance is redundant.
- Rewrote `--install` to: regenerate hwconfig (now via
  `nixos-generate-config --no-filesystems --show-hardware-config`,
  without `--root` so it inspects the live installer kernel), git
  add, eval the host's `disko.devices.disk.main.device` to resolve
  the target disk, build `config.system.build.diskoScript`, confirm
  with YES, execute disko, then nixos-install with the existing
  niri-cachix substituter args.
- Added `--disk </dev/...>` override for cross-machine reuse of the
  same host config.
- Added `--no-regen-hwconfig` opt-out for repeat installs where the
  on-disk hwconfig is already authoritative.
- Updated `do_install_post`'s next-steps text to document the
  one-time hibernate-resume wart (first boot's cmdline still has
  `resume_offset=0`; copy the value from
  `battery-resume-offset.service` and rebuild) instead of claiming
  resume was wired correctly.
- Trimmed `require_tool` to drop `wipefs`/`sgdisk`/`parted`/`mkfs.*`
  — those tools come from the disko script's `PATH=` at runtime.

## Trade-offs

- **First-boot hibernate-resume**: previously the install-time
  provisioning baked the right `resume_offset` into the cmdline
  before first boot, so resume worked on cold install. Now first
  boot's cmdline ships `resume_offset=0`; the user reads
  `battery-resume-offset.service`'s dmesg warning, edits the host
  bridge, rebuilds, reboots once. Documented as a one-time wart.
- **m-pc bios-boot path is unverified**: only the laptops have been
  exercised with disko + the bare-metal layout in smoke builds. The
  grub-on-bios-boot install path will be exercised when m-pc is
  re-imaged.

## Verification

- `nix flake check --impure` — all checks passed for all four hosts
  + WSL configs.
- `nix build .#nixosConfigurations.<h>.config.system.build.toplevel`
  for pb-x1 (real) and pb-t480/m-pc/ah-1 (`NIXOS_ALLOW_PLACEHOLDER=1
  --impure`) — all build clean.
- `nix build
  .#nixosConfigurations.{pb-x1,ah-1}.config.system.build.diskoScript`
  — both produce executable scripts targeting `/dev/nvme0n1` and
  `/dev/vda` respectively.
- `scripts/host-setup.sh --help` and arg-parsing error paths
  (`--install` without hostname, no mode flag) behave correctly.

## Out of scope (deferred)

- Snapper / btrfs automatic snapshot rotation (the `/.snapshots`
  subvol is provisioned but not wired into snapper yet).
- LUKS encryption.
- ZFS-on-root.
- Migrating pb-x1 in place. The decision was to re-image, so we
  only built the spec, not a migration path.
- Using disko's `swap.swapfile.size` so disko (not NixOS's
  swapDevices via battery.nix) owns the swapfile. That would
  eliminate the first-boot hibernate-resume wart but requires
  refactoring battery.nix to publish `swapSizeGiB` as a value disko
  can read at evaluation time.
