# Optional LUKS for disko layouts + egghead

Follow-up to the disko + egghead session earlier the same day. The
user asked for "optional LUKS setup in disko". The result is a single
opt-in flag plumbed from the egghead wizard down into the disko
layout factories, with no change to existing hosts.

## What landed

- **`flake-modules/disko.nix`** — both `diskoLayouts.bare-metal` and
  `diskoLayouts.vm` factories now accept `luks ? false`. When set,
  the `nixos` partition's content is wrapped in a disko
  `type = "luks"` block (mapper name `cryptroot`, `allowDiscards`
  + `bypassWorkqueues` on for SSD/NVMe). Header docstring rewritten
  to document the new signature and the hibernate-resume rationale.
- **`scripts/egghead.sh`** — new `EGGHEAD_LUKS` prompt (defaults
  `no`). Documented in `--help`, surfaced in the pre-write summary,
  and threaded into the generated bridge as
  `(diskoLayouts.<layout> { disk = "..."; luks = <bool>; })`.

## Design decisions

- **Mapper name fixed to `cryptroot`.** No reason to expose it; one
  encrypted volume per host is the only shape the wizard supports.
- **No passphrase handling in the flake.** disko's install-time
  `cryptsetup luksFormat` prompts on TTY. The passphrase never
  enters the nix store. Boot-time unlock prompt is wired
  automatically: the disko NixOS module emits
  `boot.initrd.luks.devices.cryptroot` from the layout.
- **Swap stays inside the encrypted btrfs** (on the `swap` subvol),
  so hibernate-resume keeps working — the LUKS volume is unlocked
  in early initrd before the kernel reads the resume image at
  `resume_offset`. No changes to `battery.nix` swap-offset logic.
- **TPM unlock deferred.** Plain passphrase prompt every boot; can
  be layered on later without changing the factory signature.
- **`luks = false` is the default** so every existing host bridge
  (`pb-x1`, `pb-t480`, `m-pc`, `ah-1`) builds bit-for-bit the same.

## Verified

- `nix build .#nixosConfigurations.pb-x1.config.system.build.toplevel`
  and the same for `ah-1` (placeholder) — both succeed unchanged
  after the factory refactor.
- End-to-end wizard run with `EGGHEAD_LUKS=yes` against a scratch
  checkout produces a host whose `toplevel` builds, whose
  `diskoScript` invokes `cryptsetup` (7 call sites), and whose
  `boot.initrd.luks.devices` attrset is `[ "cryptroot" ]`.

## Out of scope / deferred

- Retrofitting LUKS onto an already-installed host. Not requested.
- Keyfile / USB-stick unattended unlock.
- TPM2-bound unlock via `systemd-cryptenroll`.
- A separate `/boot` policy (currently the ESP at `/boot` is
  outside the LUKS volume, which is correct and intentional).
