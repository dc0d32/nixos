# 2026-05-16 — egghead: opinionated installer wizard (phase 1)

## Why

Hand-rolling `flake-modules/hosts/<name>.nix` for every new machine
works but pushes friction onto the moment when friction matters most:
the first boot of new hardware. The disko migration (same-day session
log) collapsed the partitioning ceremony to one command; this session
collapses the rest of the per-host ceremony into a single wizard that
boots from the official NixOS installer ISO, asks a handful of
questions, and hands off to `host-setup.sh --install`.

User framing:

> I get a new machine, boot from ISO/USB, open terminal and run the
> github somehow, and boom comes up a wizard. It asks for typical
> new-host things like template to use, users to allow, profiles for
> users, host name, partitioning scheme etc, then writes that new
> host into a checked out git repo locally. I can commit it as a
> proper new host if I want later, after booting in.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Delivery (phase 1) | `nix run github:dc0d32/nixos#egghead` from the official NixOS ISO | Smallest possible new-machine path; no custom ISO yet. |
| UI (phase 1) | Shell stub with `read -p` prompts + `EGGHEAD_*` env vars | Lowest dep cost; testable headlessly. |
| UI (phase 3, deferred) | TypeScript + Ink TUI | Matches Copilot CLI / Claude Code stack. |
| Wizard surface | Full per-feature toggles from day one, presets driven by role | Avoids a two-tier "easy" vs "advanced" split. |
| Role templates | `bare-metal-laptop` / `bare-metal-desktop` / `vm-headless` / `vm-desktop` | Map 1:1 to the existing host bridges; layout (`bare-metal`/`vm`) implied by role. |
| HM profile enum | `base` / `dev` / `desktop` / `kid` | Direct map to existing `flake-modules/bundles/home-*.nix`. |
| Commit policy | Auto-commit after writing files; first-boot amend if hwconfig diverged | Keeps git history clean and fixes the "installer kernel ≠ installed kernel" hwconfig drift. |
| Branding | `egghead` | Short, evocative, no existing package conflict. |

## What landed

### `scripts/egghead.sh`
Wizard script. Honours `EGGHEAD_<NAME>` env vars for every prompt
(distinguishes "set but empty" from "unset" via `${!name+x}`), then
emits a host bridge + placeholder/real hwconfig via heredoc, commits,
and execs `scripts/host-setup.sh --install <host> --no-regen-hwconfig
--disk <disk>`. Helpers: `ask`, `ask_choice`, `ask_yesno`,
`role_lookup`, `emit_bridge`, `emit_real_hwconfig`,
`emit_placeholder_hwconfig`, `do_commit`, `do_install`.

Role table is plain bash globals (`role_<name>_layout`,
`role_<name>_features`, etc.); `role_lookup` does the indirect read
via `${!key}`. shellcheck SC2034 false positives are suppressed in
the writeShellApplication wrapper.

Common feature set every generated bridge gets (always-on substrate):
`nix-settings networking openssh users system-utils locale fonts boot
home-manager-bootstrap` + `egghead-amend`.

### `flake-modules/egghead.nix`
Publishes `packages.<system>.egghead` via `writeShellApplication`
(reads the script via `builtins.readFile ../scripts/egghead.sh`,
shellcheck excludes: SC2034 / SC2153 / SC2317 / SC2155).

Also declares `flake.modules.nixos.egghead-amend`: a oneshot system
service that, on first boot, regenerates `hardware-configuration.nix`
in the primary user's `~/nixos`, commits any diff against the
egghead commit, and writes a per-host sentinel
(`/var/lib/egghead/amended-<host>`) so it never runs again unless
the sentinel is removed manually. Uses `nixos-install-tools` for
`nixos-generate-config`, runs as root with `sudo -u <primary>` for
the git operations.

### `scripts/host-setup.sh` — `do_clone_sources` fix
Pre-existing bug: bridge file was only copied into the user clone
if `dst_bridge` already existed, but for brand-new hosts the clone
from origin/main has no `flake-modules/hosts/<new>.nix` yet, so the
fresh egghead-emitted bridge would be silently dropped. Changed to
copy unconditionally when `src_bridge` exists, creating the parent
dir + fixing ownership.

### Docs
- `README.md` "Adding a new host" split into "Wizard" + "Hand-rolled"
  sub-sections; "Installing on real hardware" reworked to point at
  egghead first.
- `AGENTS.md` same split.

## Architecture decisions worth remembering

### `EGGHEAD_*` env-var contract distinct from internal var names
First attempt had `ask HOSTNAME …` reading `$HOSTNAME` directly,
which collided with bash's auto-populated `$HOSTNAME` from the
running system. Rewrote `ask` to look up `EGGHEAD_<VAR>` regardless
of what internal var name is being set — this keeps the public
contract (`EGGHEAD_HOSTNAME=…`) stable across any future renames
of the internal wizard variables.

### Placeholder hwconfig vs disko vs `nixpkgs.hostPlatform`
First placeholder draft was minimal (`{ lib, … }: { assertions = …; }`)
and failed to evaluate with
"Neither nixpkgs.hostPlatform nor nixpkgs.system has been set".
Final shape mirrors the `ah-1`/`m-pc` placeholders: imports
`installer/scan/not-detected.nix`, sets empty `boot.initrd.*`
attrs, defaults `nixpkgs.hostPlatform` to `x86_64-linux` via
`lib.mkDefault`, and asserts on `NIXOS_ALLOW_PLACEHOLDER`. Disko
still owns `fileSystems.*` / `swapDevices`, so the file is silent
on filesystems even after regeneration.

### Wizard commits with throwaway identity
The installer ISO has no global git config; the wizard sets a
local `user.email = egghead@local` / `user.name = egghead` in the
cloned working tree only when none exists. The amend service does
the same with `egghead-amend@local` in the primary user's clone.
Real human identity gets used on the next push from the booted
system.

### Always-on substrate vs role-specific add-ons
Common features (`nix-settings networking openssh users
system-utils locale fonts boot home-manager-bootstrap` +
`egghead-amend`) are imported into every generated bridge.
Role-specific add-ons (battery, biometrics, niri, etc.) layer on
top. Unattended hosts additionally get `auto-upgrade`,
`nixos-clone`, `hm-auto-upgrade`. This split keeps the role
templates short and the always-on contract explicit.

## Verified

- `nix build .#packages.x86_64-linux.egghead` — builds clean,
  shellcheck passes.
- `nix run .#egghead -- --help` — prints help, no eval errors.
- Non-interactive end-to-end via `EGGHEAD_*` env vars against a
  scratch checkout: emits bridge + placeholder hwconfig, commits.
- `NIXOS_ALLOW_PLACEHOLDER=1 nix build --impure
  .#nixosConfigurations.sl3-test.config.system.build.toplevel`
  on the generated `sl3-test` host (bare-metal-laptop, /dev/sda,
  primary user `p`, all default features incl. battery, biometrics,
  niri, quickshell, gpu=intel) — builds clean, including the
  `egghead-amend` unit.
- `NIXOS_ALLOW_PLACEHOLDER=1 nix flake check --impure` — all checks
  pass.
- Smoke build of all four existing hosts (`pb-x1`, `pb-t480`,
  `m-pc`, `ah-1`) — unchanged, clean.

## Open / not in scope

- **Custom installer ISO** (phase 2). Lifts the "boot the official
  ISO first, then `nix run` something" step. Will be a
  `nixosConfigurations.installer.config.system.build.isoImage`
  with egghead + flake source baked in and an MOTD that explains
  how to launch it.
- **TUI rewrite** (phase 3). Same prompts, same outputs, TypeScript
  + Ink for a saner UX. The shell-stub's `EGGHEAD_*` env-var
  contract is the cross-version stable interface.
- **Test on Surface Laptop 3 (Intel)**. User has one on standby;
  secure boot must be disabled in firmware (no lanzaboote in this
  flake yet). Surface-specific kernel modules (cameras, touchscreen
  fine-tuning) deferred; `bare-metal-laptop` role + generic Intel
  driver is enough for v1.
- **Multi-disk layouts**, **encrypted root**, **separate /home
  device**, **swap on a dedicated partition**: all the diskoLayouts
  factory variants we don't have yet. The wizard hard-codes the
  single-disk bare-metal / vm pair.
- **Validation of feature names against actual `flake-modules/`
  files**: wizard currently trusts the operator. Misspelt feature
  names surface as `attribute ... missing` only at
  `nix flake check` time.
- **Per-host extras** — battery thresholds, audio autoloads,
  multi-battery names, GPU PRIME setups — the wizard emits sensible
  defaults and a comment pointing at the bridge file. Tune by hand
  after first boot.
